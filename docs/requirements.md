# md2html 要件定義書 (Requirements Specification)

## 1. プロジェクト概要 & 背景 (Overview & Background)

### 1.1 目的
`md2html` は、Markdown 形式で記述された仕様書、技術文書、レポート等を、**外部ネットワーク依存のない完全スタンドアロンな単一 HTML ファイル（Single-File HTML）** へ変換するコマンドラインツールである。

### 1.2 背景・課題
- **外部依存の制約**: 一般的な Markdown ビューアや変換ツールでは、CSS や JavaScript（Mermaid、シンタックスハイライト等）を外部 CDN からロードする構成が多く、閉域網・オフライン環境やセキュリティ制限のある環境でレイアウト崩れやスクリプト実行不可が生じる。
- **ドキュメント配布の煩雑さ**: 関連する CSS / JS / 画像ファイルが別体になっていると、メール添付やファイルサーバ共有時にリンク切れや欠損が発生しやすい。
- **表現力と閲覧性の不足**: 素の HTML 変換では、警告・補足などの注意書きブロック（Admonition）、長文ドキュメント閲覧時の目次ナビゲーション（ミニマップ）、コードブロックのコピー機能などのユーザビリティが不足する。

### 1.3 想定利用シナリオ
1. **社内・閉域網での仕様書共有**: 外部通信が遮断された環境での設計書・マニュアル配布。
2. **CI/CD パイプラインでの自動ビルド**: GitLab CI / GitHub Actions 等でドキュメントを定期ビルドし、単一 HTML としてアーティファクト公開。
3. **ローカルプレビュー & ドキュメント作成**: CLI から即座に変換し、ブラウザで完成版レイアウト（GitHub/GitLab スタイル）を確認。

---

## 2. システム範囲 (System Scope)

### 2.1 対象範囲 (In-Scope)
- Markdown から単一 HTML への変換処理。
- GitHub / GitLab 風スタイルシートおよび Admonition / コピーボタン / ミニマップ用 CSS のインライン埋め込み。
- Mermaid.js によるクライアントサイドダイアグラム描画（インラインスクリプト）。
- Pygments によるシンタックスハイライト（インライン CSS）。
- MkDocs 形式および Docusaurus 形式の Admonition 構文サポート。
- 見出し（h1〜h6）抽出とアンカー ID 付与、ミニマップ（TOC）サイドバーの自動生成。
- CLI コマンドインターフェース（ファイル指定、標準入出力対応）。

### 2.2 対象外 (Out-of-Scope)
- 外部画像ファイル（ローカル相対パス画像）の Base64 自動変換（将来拡張検討）。
- Web サーバ機能やリアルタイムライブリロード機能（HTTP サーバは内包しない）。
- PDF や Word (docx) 等、HTML 以外のフォーマット出力。

## 3. 機能要件 (Functional Requirements)

### FR-1: Markdown 構文パース & HTML 変換
- **FR-1.1 (CommonMark 準拠)**: 見出し、段落、リスト（順序・順序なし・ネスト）、強調、引用、水平線、リンク、コード等の標準構文を正確に HTML へ変換できること。
- **FR-1.2 (GFM 拡張)**: テーブル記法、取り消し線（`~~text~~`）、生 URL の自動リンク化をサポートすること。
- **FR-1.3 (テーブル配置拡張)**: リスト項目内や引用ブロック内にインデント配置されたテーブルを正常にパースできること。
- **FR-1.4 (Front Matter 処理)**: 文頭の YAML / Docusaurus 形式 Front Matter（`---` で囲まれたブロック）を本文から除外し、`title:` 属性が定義されている場合はドキュメントの `<title>` タグに反映すること。
- **FR-1.5 (HTML パススルー)**: Markdown 内に直接記述された生の HTML タグをエスケープせず、そのまま出力できること（`escape=False`）。

### FR-2: スタイリング & テーマ制御
- **FR-2.1 (テーマ選択)**:
  - `github` テーマ: GitHub の README / レポジトリスタイルを踏襲したデザイン。
  - `gitlab` テーマ: GitLab の Wiki / ドキュメントスタイルを踏襲したデザイン。
  - `auto` テーマ: GitHub スタイルをベースとしつつ、ダークモード時に GitLab スタイルの配色変数を適用。
- **FR-2.2 (カラーモード制御)**:
  - `--mode auto` (デフォルト): OS / ブラウザの `prefers-color-scheme: dark` に応じて自動切り替え。
  - `--mode light`: ライトモード固定（ダーク用メディアクエリを除去）。
  - `--mode dark`: ダークモード固定（ダーク用メディアクエリを無条件適用）。
- **FR-2.3 (本文レイアウト)**: 最大幅 980px の中央揃え配置とし、レスポンシブ表示に対応すること。

### FR-3: コードハイライト & コピー支援
- **FR-3.1 (シンタックスハイライト)**:
  - Pygments を使用し、コードブロックの言語識別子に応じたトークンハイライトを行うこと。
  - 主要言語（Python, JavaScript, TypeScript, Go, Rust, Java, C/C++, HTML, CSS, Bash, SQL, JSON, YAML 等）を自動認識すること。
  - 言語未指定または未知言語の場合は、エスケープされたプレーンコードブロックとして安全に出力すること。
  - `--highlight-style` オプションにより、Pygments のカラースキーム（デフォルト: `default`）を変更可能とすること。
  - `--no-highlight` オプションにより、ハイライト処理を無効化できること。
- **FR-3.2 (コードコピーボタン)**:
  - すべてのコードブロックにホバー時表示される「Copy」ボタンを自動付与すること。
  - クリック時にクリップボードへコード文字列をコピーし、フィードバック表示（「✓ Copied」）を行うこと。
  - クリップボード API (`navigator.clipboard`) およびフォールバック (`execCommand`) に対応すること。
  - Mermaid 図ブロックにはコピーボタンを付与しないこと。

### FR-4: Mermaid ダイアグラム描画
- **FR-4.1 (図のクライアントレンダリング)**:
  - 言語識別子が `mermaid` のフェンスコードブロックを `<pre class="mermaid">` に変換し、HTML 閲覧時にブラウザ側で SVG 描画すること。
  - フローチャート、シーケンス図、ガントチャート、クラス図、状態遷移図、ER 図等、Mermaid.js が対応する主要ダイアグラムに対応すること。
- **FR-4.2 (テーマ連動)**:
  - カラーモードに応じて Mermaid のテーマ（ライト時: `default`, ダーク時: `dark`）を適切に適用すること。
- **FR-4.3 (無効化制御)**:
  - `--no-mermaid` オプション指定時は Mermaid スクリプトの埋め込みを行わず、通常のコードブロックとして出力すること。

### FR-5: Admonitions (注意書きブロック) 処理
- **FR-5.1 (MkDocs 構文サポート)**:
  - `!!! <type> ["タイトル"]` 形式の構文を解析し、`<div class="admonition <type>">` に変換すること。
  - 対象タイプ: `note`, `info`, `tip`, `success`, `warning`, `danger`, `failure`, `bug`, `example`, `quote`, `abstract`。
  - 4文字インデントによる複数行本文の保持およびネストをサポートすること。
- **FR-5.2 (Docusaurus 構文サポート)**:
  - `:::<type>[ タイトル]` 〜 `:::` 形式の構文を解析し、同様の Admonition HTML に変換すること。
  - 対象タイプ: `note`, `tip`, `info`, `caution`, `danger`, `warning`。
- **FR-5.3 (タイトル自動補完 & アイコン)**:
  - タイトルが省略された場合、タイプ名を大文字開始に変換（例: `note` → `Note`）してデフォルトタイトルとすること。
  - タイプごとに固有のボーダー色および絵文字アイコンを表示すること。

### FR-6: ミニマップ (TOC / 目次サイドバー) & アンカーナビゲーション
- **FR-6.1 (見出し抽出 & アンカー付与)**:
  - HTML 内の `<h1>` 〜 `<h6>` 見出しを自動抽出すること。
  - 各見出しに一意なアンカー ID を自動付与すること（見出しテキストからスラッグ生成）。
  - 日本語（漢字、ひらがな、カタカナ、全角文字）を含むマルチバイト文字に対応すること。
  - 重複見出しが存在する場合、`-1`, `-2` 等の連番サフィックスを付与してアンカー衝突を回避すること。
- **FR-6.2 (ミニマップ表示 & スクロール追従)**:
  - ドキュメント右側上部に固定追従（`position: sticky; top: 24px;`）する目次サイドバーを生成すること。
  - 見出しレベルに応じたインデント階層を表示すること。
  - スクロール位置および URL ハッシュに連動して、現在閲覧中の見出し項目をアクティブ表示（`.active`）すること。
- **FR-6.3 (無効化オプション)**:
  - `--no-minimap` または `--no-toc` オプション指定時は、ミニマップ HTML およびスクリプトを一切注入しないこと。

### FR-7: CLI & マルチファイルサイト構築
- **FR-7.1 (引数体系)**:
  - `md2html [OPTIONS] INPUT [OUTPUT]`
  - `INPUT`: 起点となる Markdown ファイルパス。`-` の場合は標準入力 (stdin) から読み込み。
  - `OUTPUT`: 出力先フォルダパス（デフォルト: `dist`）。stdin 入力時は標準出力 (stdout) へ出力（指定時はフォルダ内の `index.html` に出力）。
- **FR-7.2 (CLI オプション一覧)**:
  - `--title TEXT`: `<title>` タグの文字列（起点ドキュメントに適用。省略時: ファイル名または Front Matter の title）。
  - `--theme {github,gitlab,auto}`: テーマ選択（デフォルト: `github`）。
  - `--mode {auto,light,dark}`: カラーモード（デフォルト: `auto`）。
  - `--highlight-style TEXT`: Pygments カラースキーム（デフォルト: `default`）。
  - `--no-highlight`: シンタックスハイライト無効化。
  - `--no-mermaid`: Mermaid 描画無効化。
  - `--no-minimap` / `--no-toc`: ミニマップ（目次）非表示。
  - `-h, --help`: ヘルプメッセージ表示。
- **FR-7.3 (終了ステータス)**:
  - 正常終了時は終了コード `0` を返却すること。
  - 引数不正、ファイル読み込み失敗、変換エラー等の異常終了時は標準エラー出力にエラーメッセージを出力し、非ゼロ（`1` 等）を返却すること。
- **FR-7.4 (リンク先 Markdown の連鎖変換)**:
  - 起点 Markdown から相対パスでリンクされている別の Markdown ファイル（`.md`, `.markdown`）を再帰的に探索し、すべて HTML へ変換して出力フォルダ内に保存すること。
  - 生成された各 HTML 内の `.md` への相対リンクを、出力先の `.html` パスへ自動書き換えすること（アンカーハッシュ `#section` やクエリは保持）。
  - 循環リンク（A → B → A）が存在しても無限ループに陥らないこと。
- **FR-7.5 (非 Markdown アセットの自動コピー)**:
  - Markdown 内で参照されている画像（`<img>`）やリンクされた非 Markdown ファイル（PDF、ZIP 等）について、HTML からの相対パス関係を維持できるように出力フォルダ内にサブディレクトリを作成し、当該ファイルをコピーすること。

## 4. 非機能要件 (Non-Functional Requirements)

### NFR-1: スタンドアロン性 (ゼロ外部依存)
- 生成される HTML ファイルは、**完全なオフライン環境で動作・完結**すること。
- 外部 CDN、リモートホスト、外部 CSS/JS ファイルへの `<link>` や `<script src="...">` を一切含まないこと。
- すべての CSS、JavaScript、スタイル定義は HTML 内にインライン（`<style>`, `<script>`）で埋め込むこと。

### NFR-2: 動作環境・互換性
- **実行環境**:
  - Python 3.11 以上（Linux, macOS, Windows）。
- **出力 HTML の閲覧環境**:
  - 主要モダンブラウザ（Google Chrome, Mozilla Firefox, Apple Safari, Microsoft Edge 各最新版）。
- **レスポンシブ対応**:
  - PC（幅 1024px 以上）では本文＋右側ミニマップの 2 カラム表示。
  - タブレット・モバイル（幅 1024px 未満）では画面幅に応じた最適化配置。

### NFR-3: パフォーマンス & 信頼性
- 数千行規模の Markdown ドキュメントであっても、CLI 実行から数秒以内で変換処理が完了すること。
- 過剰な再パースや二重処理を避け、メモリ使用量を抑制すること。

### NFR-4: 国際化 (i18n) & 文字コード
- 文字コードはすべて `UTF-8` を標準とし、BOM なし UTF-8 を前提とすること。
- HTML に `<meta charset="UTF-8">` および `<html lang="ja">` を明記すること。
- 日本語を含む見出しテキストから有効な URL アンカー ID（スラッグ）が生成できること。

### NFR-5: テスト品質・保守性
- **テスト駆動開発 (TDD)**: 機能追加およびバグ修正は Red → Green → Refactor サイクルを厳守すること。
- **テスト自動化**: `tox` を使用して `pytest`（単体・結合テスト、カバレッジ計測）および Lint/Format チェックがワンコマンドで検証可能であること。
- **DOM 構造検証**: テストでは `beautifulsoup4` を活用し、生成 HTML の DOM 要素や属性値を確実にアサーションすること。
- **静的解析**: `ruff` (format/check) および `flake8` による検証を通過し、行長 100 文字規約に適合すること。

## 5. 制約事項 & 前提条件 (Constraints & Assumptions)

1. **Python 依存パッケージの最小化**:
   - 実行時依存（`requirements.txt`）はコア機能に必要な `mistune` および `pygments` のみに限定し、不要なサードパーティライブラリを追加しない。
2. **アセットの同梱管理**:
   - スタイルシート（CSS）およびクライアント側 JS は `src/md2html/assets/` に同梱し、パッケージ内に含めて配布・利用可能とする。
3. **MRO（メソッド解決順序）の維持**:
   - レンダラー拡張時は、`CombinedRenderer` における Mermaid と Pygments の優先順位を崩さないこと。
